# Codex 추가 리뷰 — 도트 네온

## 요약
새로 발견한 문제 수: 높음 0 / 중간 3 / 낮음 0(메인 페이지 연동 포함). 기본 팔레트 색 변수는 블로그와 이름·값이 일치하고, 화면에 조작 안내가 있습니다. 코드 검토와 Node 실행으로 확인했으며 iframe 높이 지적은 코드 계산에 따른 추정입니다.

## 발견한 문제
### 1. 진행 중인 포인터 획이 페이지 종료 시 저장되지 않을 수 있음 — 심각도: 중간
- 위치: `apps/dot-neon/main.js:223`, `apps/dot-neon/main.js:669`
- 문제: 픽셀은 획 도중 즉시 바뀌지만 저장 예약은 `endStroke()`에서만 합니다. `pagehide`는 `saveTimer !== null`일 때만 저장하므로, 이전 저장이 끝난 상태에서 시작한 미완료 획은 저장하지 않습니다. 포인터 획에는 blur 종료 처리도 없습니다.
- 재현/근거: 저장 타이머가 끝난 뒤 마우스를 누른 채 그리다가, 놓기 전에 Ctrl+R로 새로고침합니다. `extendStroke()`는 픽셀만 갱신하고 저장을 예약하지 않으며, `pagehide`도 타이머가 null이면 아무것도 하지 않습니다. 마지막 완료 획 이후의 그림이 사라지는 코드 경로입니다. 실제 브라우저 이벤트 순서는 미검증입니다.
- 제안: `pagehide`에서 진행 중인 획까지 확정하고 현재 상태를 반드시 저장합니다. 모바일 앱 전환을 위해 `visibilitychange`의 hidden 상태에서도 저장을 고려합니다.

### 2. 포인터 획 도중 키보드 칠하기가 끼어들면 되돌리기 단위가 섞임 — 심각도: 중간
- 위치: `apps/dot-neon/main.js:252`, `apps/dot-neon/main.js:426`
- 문제: Space/Enter의 `applyAt()`는 진행 중인 포인터 획을 종료하지 않고 현재 그림 전체를 기록합니다. 이후 포인터 획이 계속되면 앞부분과 뒷부분이 서로 다른 기록에 들어가 “드래그 한 번 = 되돌리기 한 단계”가 깨집니다.
- 재현/근거: 펜으로 첫 칸을 누른 채 유지 → 방향키로 다른 행으로 커서 이동 → Space → 포인터를 다음 칸으로 이동 → 놓기. 실제 main.js에서 import와 init 호출만 제거해 Node에서 함수를 실행하고 화면·저장 함수만 대체했습니다. `beginStroke → extendStroke(0) → applyAt(16) → extendStroke(1) → endStroke` 후 첫 undo에는 `[0,16]`이 남고, 두 번째 undo는 빈 그림이 됩니다. 한 드래그의 0번 칸과 1번 칸이 함께 되돌아가지 않습니다.
- 제안: 키보드의 독립 칠하기 전에 `endStroke()`를 호출하거나, 포인터 획이 활성화된 동안 키보드 편집 입력을 일관되게 제한합니다.

## review.md와 다른 의견
- “드래그 1번 = 기록 1개” 통과는 포인터·키보드 혼합 입력에서는 성립하지 않습니다.
- `pagehide`의 즉시 저장은 예약된 저장에만 적용됩니다. 진행 중인 포인터 획까지 보존한다는 결론으로 확대할 수 없습니다.
- 기본 색·사용법 안내는 규칙을 충족합니다. reduced-motion CSS는 애니메이션을 끄며, 실제 기기·스크린 리더·다운로드 동작은 이번에도 검증하지 않았습니다.

## 메인 페이지 연동
### 3. 바깥 화면 너비로 iframe 높이를 줄여 내부 1단 배치와 어긋남 — 심각도: 중간 (추정)
- 위치: `css/style.css:712`, `apps/dot-neon/style.css:462`, `index.html:59`
- 문제: 부모 화면이 1000px 이상이면 iframe 높이를 900px로 줄이지만, 앱의 2단 배치는 iframe 자체 너비가 720px 이상일 때만 적용됩니다. 사이드바와 카드 여백 때문에 이 두 조건은 일치하지 않습니다.
- 재현/근거: 부모 폭 1000px에서 사이드바 260px, 섹션 좌우 여백 96px, 카드 좌우 패딩 2.5rem 및 테두리를 빼면 iframe 폭은 약 595px입니다. 앱은 1단 배치와 420px 격자를 유지합니다. 제목·도구·팔레트·저장·도움말이 아래로 쌓여 900px를 넘을 것으로 계산되며, 내부 세로 스크롤과 하단 조작 접근 불편이 예상됩니다. 실제 높이·스크롤은 브라우저에서 미측정했습니다.
- 제안: iframe의 실제 너비 또는 내부 콘텐츠 높이에 맞춰 높이를 정합니다. 고정 높이를 유지한다면 내부가 1단인 폭 구간에서는 충분한 높이를 유지합니다.
