## 요약
**통과.** spec.md 9절 체크리스트 19개 항목을 모두 확인했고 고칠 버그는 없었습니다. 코드는 수정하지 않았습니다.
Build가 spec과 다르게 한 8가지는 아래 "spec과 다른 부분 판단"에 정리했습니다. 모두 타당하다고 봅니다.

확인 환경: Node(logic.js 단위 테스트 49개), 내장 브라우저(Chromium, `http://localhost:8000/apps/dot-neon/index.html`).

## spec과 다른 부분 판단
| Build가 바꾼 점 | 판단 |
|---|---|
| PNG는 한 번에 한 장(표의 "5장"은 오타) | 타당. 5절 본문과 배율 선택 구조가 한 장 저장을 전제로 함 |
| 같은 색 채우기·빈 그림 전체 지우기는 기록 없이 알림만 | 타당. "그림을 바꾸지 않는 동작은 기록에 남기지 않음" 규칙과 맞고, 알림이 있어 눌렀는데 반응이 없는 것처럼 보이지 않음 |
| 빈 그림 저장 알림 두 개를 하나로 | 타당. "동작당 1회" 알림 규칙에 맞음. 실제 문구 "PNG 저장: 512×512. 빈 그림이라 투명한 이미지예요" 확인 |
| 스포이트로 팔레트에 없는 색을 집으면 사용자 색 칸에 넣음 | 타당. 그렇게 하지 않으면 선택 표시가 아무 칸에도 없게 됨. 다만 이전에 고른 사용자 색은 덮어써짐(아래 참고 사항) |
| 키보드 커서를 `show-cursor` 클래스로 표시 | 타당. 키보드를 쓸 때만 커서가 보이고 포인터로 그릴 때는 숨김. 실제 키 입력으로 cyan 이중 테두리 표시 확인 |
| `pagehide`에서 바로 저장 | 타당. 300ms 지연 저장 중 페이지를 떠나도 잃지 않음. pagehide 직후 localStorage에 반영된 것 확인 |
| 720px 이상에서 최대 폭 880px, 격자 min(420px, 100vw - 336px) | 타당. 480px로는 2단 배치가 안 됨. 720px에서 격자 384px + 오른쪽 열 280px, 가로 스크롤 없음 |
| 사용자 색 칸 포커스 외곽선이 `:has()`에 의존 | 수용 가능. 현재 주요 브라우저(Chrome 105+, Safari 15.4+, Firefox 121+)는 지원. 이보다 오래된 브라우저에서는 이 칸에만 포커스 외곽선이 안 보임 |

## 발견한 문제와 수정 사항
- 수정 사항: 없음.
- 참고(고치지 않음, 사소함):
  - 스포이트로 팔레트 밖 색을 집으면 이전 사용자 색이 바뀜. 의도된 동작으로 봄.
  - 사용자 색 칸은 `<input type="color">`라서 aria-pressed가 없음. 선택 상태는 화면의 테두리·✓와 "현재:" 표시줄, 알림으로 전달됨.
  - 일반 버튼 테두리(`--btn-line`)는 배경 대비 2.09:1이지만 버튼 안 글자로 구분되므로 WCAG 1.4.11 위반은 아님.
  - 320px에서 칸 크기는 spec의 약 18px이 아니라 약 16.8px(칸 사이 1px 선 때문). 사용에 문제 없음.

## 확인하지 못한 것
- 실제 휴대폰·태블릿 기기와 펜 입력(모바일 에뮬레이션과 PointerEvent로만 확인).
- Safari·Firefox 실제 동작(Chromium만 확인).
- 실제 파일 다운로드(지침대로 blob만 검사).
- `prefers-reduced-motion` 미디어 에뮬레이션(CSS 규칙으로만 확인).
- 블로그 메인 페이지 iframe 안 동작(아직 Embed 전이라 임시 iframe 375px로만 확인).
- 화면 읽기 프로그램으로 실제 낭독(속성 값만 확인).
