오늘 Claude Code와 함께 이 블로그를 처음부터 만들었습니다. 프레임워크 없이 HTML, CSS, JavaScript만 썼더니 세 가지가 각자 무슨 일을 하는지 또렷하게 보였습니다.

한 줄로 줄이면 이렇습니다.

> HTML은 **뼈대**, CSS는 **옷**, JavaScript는 **움직임**이다.

## HTML: 무엇이 있는지 정한다

HTML은 페이지에 어떤 내용이 어떤 순서로 들어가는지 정합니다. 이 블로그의 `index.html`에는 머리말(헤더), 본문 자리, 꼬리말(푸터)만 들어 있습니다.

```html
<header class="site-header">…</header>
<main id="app">불러오는 중…</main>
<footer class="site-footer">…</footer>
```

- `<header>`, `<main>`, `<footer>`처럼 **의미 있는 태그**를 쓰면 화면 낭독기도 구조를 이해합니다.
- `<meta name="viewport">` 한 줄이 있어야 휴대폰에서 화면이 작게 쪼그라들지 않습니다.

## CSS: 어떻게 보이는지 정한다

CSS는 색, 글자 크기, 여백, 배치를 맡습니다. 같은 HTML이라도 CSS에 따라 전혀 다른 모습이 됩니다.

- **CSS 변수**: 색을 `--text`, `--bg` 같은 이름으로 한곳에 모아 두면, 다크 모드에서는 그 값만 바꾸면 됩니다.
- **미디어 쿼리**: `@media (min-width: 768px)`로 화면이 넓을 때만 여백을 늘렸습니다. 작은 화면을 먼저 만들고 넓은 화면을 덧붙이는 방식을 *모바일 우선*이라고 부릅니다.
- **읽기 좋은 글**: 본문 폭을 너무 넓지 않게 하고, 줄 간격을 넉넉히 두고, `word-break: keep-all`로 한글 단어가 중간에서 끊기지 않게 했습니다.

```css
:root { --header-text: #a16207; }
:root[data-theme="dark"] { --header-text: #ffd43b; }
```

헤더 글자를 노란색으로 바꿀 때도 위처럼 변수 두 개만 고쳤습니다.

## JavaScript: 무엇을 할지 정한다

JavaScript는 사용자의 행동에 반응하고, 필요한 내용을 불러와 화면을 바꿉니다.

1. **글 불러오기**: `fetch`로 `posts/*.md` 파일을 읽어 옵니다.
2. **마크다운 변환**: `# 제목`, `**굵게**` 같은 글을 HTML 태그로 바꿉니다.
3. **화면 전환**: 주소의 `#/post/…` 부분을 보고 목록을 보여줄지, 글을 보여줄지 정합니다.
4. **다크 모드 버튼**: 누르면 테마를 바꾸고, 고른 값을 브라우저에 저장합니다.

글 내용을 화면에 넣기 전에 `<`, `>` 같은 기호를 글자로 바꿔 두는 것도 JavaScript의 일입니다. 그래야 글 안에 적힌 `<script>`가 실행되지 않습니다.

## 정리

| 언어 | 역할 | 이 블로그에서 |
| :--- | :--- | :--- |
| HTML | 내용과 구조 | `index.html`의 헤더·본문·푸터 |
| CSS | 모양과 배치 | 색 변수, 다크 모드, 모바일 여백 |
| JavaScript | 동작과 데이터 | 글 불러오기, 마크다운 변환, 테마 버튼 |

## 덤으로 배운 것

- 브라우저는 보안 때문에 `file://`로 연 페이지에서 다른 파일을 `fetch`하지 못합니다. 그래서 `python -m http.server`로 작은 서버를 띄워야 했습니다.
- CSS를 고쳤는데 화면이 그대로라면 브라우저가 예전 파일을 기억하고 있는 것일 수 있습니다. `Ctrl+Shift+R`로 새로고침하면 됩니다.

세 가지가 서로 맡은 일을 나눠 갖고 있다는 걸 알고 나니, 어디를 고쳐야 할지 훨씬 쉽게 떠오릅니다.
