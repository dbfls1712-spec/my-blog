이 블로그는 제가 코드를 한 줄씩 쓰지 않고, **Claude Code**에게 한국어로 부탁해서 만들었습니다. 하루 동안 함께 일해 보니 결과물보다 **일하는 방법**에서 배운 것이 더 많았습니다.

## 먼저 규칙을 적어 둔다

처음 한 일은 블로그가 아니라 `CLAUDE.md`라는 문서를 만드는 것이었습니다. 이 파일에는 프로젝트의 규칙이 들어 있습니다.

- 프레임워크 없이 HTML, CSS, JavaScript만 쓴다.
- 다크 모드를 지원하고 휴대폰에서도 잘 보이게 한다.
- 색은 CSS 변수로만 관리한다.

Claude는 작업할 때마다 이 문서를 읽기 때문에, 같은 설명을 매번 반복하지 않아도 됩니다. 사람에게 일을 맡길 때 업무 지침서를 건네는 것과 비슷합니다.

## 바로 만들지 말고 계획부터

중간에 "아직 만들지 말고 계획을 먼저 작성하자"라고 멈춘 적이 있습니다. 이때 쓴 것이 **계획 모드**입니다. 입력창 아래의 모드 메뉴에서 고르거나 `Shift+Tab`으로 바꿀 수 있습니다.

계획 모드에서 Claude는 파일을 고치지 않고 계획만 세웁니다. 그 과정에서 이런 질문을 먼저 해 왔습니다.

| 질문 | 제 답 |
| :--- | :--- |
| 마크다운 변환기를 직접 만들까, 라이브러리를 쓸까? | 직접 만들기 |
| 블로그 이름은? | RIN |
| 코드에 색을 입힐까? | 입히지 않기 |

계획을 확인하고 승인한 뒤에야 실제 작업이 시작되니, 엉뚱한 방향으로 한참 가 버리는 일이 없었습니다.

## 화면을 가리키며 말한다

"글자 색을 노란색으로 바꿔줘"라고만 하면 어디를 말하는지 모호합니다. 그래서 브라우저 화면에서 **헤더 부분을 직접 선택**한 뒤 부탁했습니다. Claude는 선택한 곳만 고쳤고, 흰 배경에서는 밝은 노란색이 잘 안 보인다며 라이트 모드에는 조금 더 짙은 노란색을 썼습니다.

> 무엇을 원하는지보다 **어디를** 원하는지 알려 주는 것이 더 중요할 때가 있다.

## 반복되는 일은 예약한다

매일 아침 8시에 웹 기초 글을 한 편씩 올리도록 **예약 작업**도 만들었습니다. 예약 작업은 대화 내용을 기억하지 못하고 매번 새로 시작합니다. 그래서 지시문에 필요한 정보를 모두 적어 두어야 합니다.

- 어느 폴더에서 일하는지
- 어떤 순서로 주제를 고르는지
- 이미 쓴 주제는 어떻게 건너뛰는지
- 무엇은 절대 건드리지 말아야 하는지

## 모르면 멈추고 묻는다

Obsidian 볼트에서 글을 가져와 달라고 했을 때, 볼트에는 블로그 폴더가 없었습니다. Claude는 아무 폴더나 뒤져 글을 올리지 않고, **찾지 못했다고 말한 뒤 어떻게 할지 물었습니다.** 그 덕분에 지금 이 글을 쓰고 있는 `50 블로그` 폴더와 템플릿이 생겼습니다.

AI가 모든 것을 알아서 해 주길 기대하기보다, 확실하지 않을 때 멈추고 묻는 편이 결과적으로 더 빠르다는 것을 느꼈습니다.

## 정리

1. 규칙은 문서로 남겨 둔다.
2. 큰 작업은 계획을 먼저 보고 승인한다.
3. 고칠 곳은 화면에서 직접 가리킨다.
4. 반복되는 일은 예약하되, 지시문은 혼자 읽어도 이해되게 쓴다.

코드를 몰라도 무엇을 원하는지 또렷하게 말할 수 있으면 생각보다 많은 것을 만들 수 있었습니다. 다음에는 이 블로그에 검색 기능을 붙여 볼 생각입니다.
