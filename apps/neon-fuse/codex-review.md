# Codex 추가 리뷰 — 네온 퓨즈

## 요약
새로 발견한 문제 수: 높음 0 / 중간 1 / 낮음 1(메인 페이지 연동 포함). 기본 팔레트 색 변수는 블로그와 이름·값이 일치하고, 화면에 조작 안내가 있습니다. 코드 검토와 Node 실행으로 확인했으며 브라우저 실측은 하지 않았습니다.

## 발견한 문제
### 1. 손상된 최고 점수 문자열을 정상 점수로 받아들임 — 심각도: 낮음
- 위치: `apps/neon-fuse/main.js:46`
- 문제: `parseInt`는 문자열 전체를 검증하지 않고 숫자 접두부만 읽습니다. 안전한 정수 범위도 검사하지 않아 비정상 최고 점수가 계속 표시되고 정상 플레이로 갱신되지 않을 수 있습니다.
- 재현/근거: `neon-fuse:best`가 `123garbage`이면 123, `1e6`이면 1로 읽힙니다. Node에서 같은 변환을 실행했으며, 9가 80개인 문자열도 유한한 `1e+80`으로 받아들였습니다(`Number.isFinite` 통과).
- 제안: 정수 문자열 전체를 검사하고 `Number.isSafeInteger` 및 음수 여부를 확인해 잘못된 값은 0으로 처리합니다.

## review.md와 다른 의견
- 블로그 복귀 링크의 URL이 올바르게 해석된다는 확인만으로 iframe 연동까지 통과로 볼 수 없습니다. 아래와 같이 현재 프레임에 블로그를 여는 문제가 있습니다.
- localStorage 접근 예외 처리는 기존 평가에 동의합니다. 다만 손상된 값의 내용 검증까지 보장하지는 않습니다.

## 메인 페이지 연동
### 2. iframe의 블로그 복귀 링크가 iframe 안에 블로그를 다시 엶 — 심각도: 중간
- 위치: `apps/neon-fuse/index.html:17`, `index.html:50`
- 문제: 복귀 링크에 `target="_top"`이 없어 메인 페이지의 게임 iframe 안에 블로그 전체가 로드됩니다. 돌아온 블로그에는 다시 앱 iframe들이 포함되어 중첩 탐색이 생깁니다.
- 재현/근거: 메인 페이지의 네온 퓨즈 iframe에서 “← 블로그로”를 누릅니다. 링크의 기본 대상은 현재 browsing context이므로 바깥 페이지가 아닌 게임 프레임이 `../../index.html`로 이동합니다. 도트 네온의 같은 링크에는 `_top`이 있습니다.
- 제안: 복귀 링크에 `target="_top"`을 지정합니다.
